# تقرير المرحلة 0 — فحص مشروع Zark

آخر تحديث: 2026-08-28

## الحالة التي وُجدت

المشروع بدأ كمجلد فارغ، ثم بُنيت نواة TypeScript صغيرة فيها API وبوت وواجهة ويب وPrisma. عند مراجعة المواصفة المعدّلة ظهر خلل معماري مهم: خدمة `quickMatch` كانت تستخدم `ترجم` كقيمة افتراضية داخل `LfgRoom`. هذا خلط ألعاب Zark الداخلية بألعاب LFG الخارجية، وكان سيؤدي إلى خلط XP بنتائج البحث عن فريق.

## ما أُعيدت هيكلته

- فصل `ZarkGame` و`ZarkMatch` و`GameProfile` عن `LfgGameCatalog` و`LfgRoom`.
- نقل منطق ألعاب السباق إلى `packages/games` بدل وضعه داخل أمر Discord.
- جعل البوت والموقع يستدعيان خدمات الـAPI؛ الوصول إلى Prisma محصور في تطبيق الـAPI.
- فصل `/play` عن `/lfg` في الأوامر والـEndpoints والواجهات.
- إزالة منح Engagement Points من الفوز اليومي؛ نقاط LFG تُمنح بعد اكتمال الجلسة فقط.
- جعل وقت السباق محسوبًا من سجلات الخادم، لا من `startedAt` يرسله العميل.
- إضافة قيد يمنع منح نفس مصدر نقاط التفاعل للمستخدم مرتين.

## الموجود والقابل للتحقق الآن

- Schema صالح لـPostgreSQL يفصل ألعاب Zark الداخلية عن كتالوج ألعاب LFG الخارجية.
- كتالوج LFG مصنّف، اهتمامات وإشعارات لكل لعبة، وإنشاء/دخول/خروج ذري مع منع التجمعات المتعارضة.
- تسجيل دعوات DM ومنع تكرارها، وحد يومي وCooldown لكل لعبة.
- Profile موحد، أفضل لاعبي LFG، تقييمات مجمعة، بلاغات لاعبين وتقارير أخطاء.
- Discord OAuth2 بجلسة HttpOnly وصلاحيات إدارة مبنية على Guild Roles.
- محرك RaceGame modular ومطابقة عربية مرنة واختبارات للنقاط والتطبيع.
- أحداث Realtime موحدة عبر Redis Pub/Sub وSSE للمتصفح، مع PostgreSQL كمصدر الحقيقة.
- موقع عربي متعدد الصفحات للرئيسية والغرف والألعاب والبروفايل والتصنيفات والدعم والإدارة.
- `npm run check` و`npm test` و`npm run build` ناجحة، و`npm audit --omit=dev` بلا ثغرات معروفة.

## الناقص قبل نشر Production

1. Scheduled LFG وScheduler موثوق وتذكير ما قبل الموعد.
2. قنوات Text/Voice المؤقتة ولوحة Host وGrace Period للحذف.
3. Voice playtime وAnti-AFK.
4. Smart Ready Checks والغرف التلقائية وQuiet Hours موزعة.
5. قرارات الإدارة الكاملة وAudit Log وتحديث Trust Score تلقائيًا.
6. المواسم والإنجازات ثم Mafia والكراسي وParty وRival.
7. Prisma migrations واختبارات تكامل حقيقية مع PostgreSQL وRedis وDiscord.

## قرار الاستمرار

البنية الحالية مناسبة للبناء عليها ولا تحتاج إعادة كتابة. المرحلة التالية المنطقية هي Scheduled LFG ثم الغرف المؤقتة، لأنهما يحولان طلب البحث عن لاعبين إلى جلسة Discord فعلية يمكن تتبعها وإكمالها وتقييمها.
